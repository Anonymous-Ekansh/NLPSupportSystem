# Decision Policy — A3 route, A4 audit, A5 decision

Every threshold below lives in [`config/l2_policy.json`](../config/l2_policy.json). It is
regenerated by [`scripts/tune_a3_policy.py`](../scripts/tune_a3_policy.py) from **DEV only**;
nothing in this document is tuned on TEST. Editing the file changes behaviour with no code change.

```json
"source": "tuned:dev"
```

## 2. A3 — routing, first match wins

| # | Condition | Route | Reason codes | Effect |
|---|---|---|---|---|
| 1 | Query empty or gibberish | `escalate` | `empty_query` / `gibberish` | No answer attempt |
| 2 | Sensitive term found | `escalate` | `sensitive_content`, `sensitive_<group>` | Human queue by group |
| 3 | `top1_similarity < ood_similarity_min` | `escalate` | `out_of_distribution` | Unsupported topic |
| 4a | Required detail missing **and** the query is a how-to question with no "I don't have it" phrase | `answer` | `informational_question` | Answers the procedure; claims no action |
| 4b | Required detail missing | `clarify` | `missing_information`, `missing_<slot>`, plus `user_lacks_slot` when the customer says they cannot supply it | Asks for exactly that item |
| 5 | `confidence < confidence_low` | `escalate` | `low_confidence` | A wrong answer is worse than a handoff |
| 6a | Ambiguous but both intents share a category | `answer` | `ambiguous_same_category`, `widened_retrieval` | Retrieval widens to `k_widened`, no interruption |
| 6b | Ambiguous across categories | `clarify` | `ambiguous_intent` | "Are you asking about X or Y?" |
| 7 | Otherwise | `answer` | `standard_retrieval` | Normal retrieval |

Every branch also appends a plain-English sentence to `RoutePlan.reasons`, which A5 copies into
the user-facing explanation and the trace.

### Required details (`nlp/l2/slots.py` + policy `slots.required`)

| Intent | Required slot |
|---|---|
| `cancel_order`, `change_order`, `track_order` | `order_number` |
| `get_refund`, `track_refund` | `order_number` |

A slot counts as satisfied only when a **usable value** is present (digits, an order-like id, an
email, an amount, a date, or a dataset placeholder such as `{{Order Number}}`). Merely mentioning
"order number" does not satisfy it. The "I don't have it" phrases (`can't find`, `lost`,
`don't have`, `forgot`, …) are listed under `slots.not_have_phrases`.

That is why `"I need a refund but cannot find my order number"` cannot reach ANSWER: `get_refund`
needs `order_number`, none is present, and the customer says they cannot find it, so A3 returns
`clarify` with `missing_order_number` and `user_lacks_slot`.

## 3. A4 — audit of the candidate response

| Check id | Passes when | Fails when |
|---|---|---|
| `intent_alignment` | Every evidence example's intent equals the prediction, and query-to-response cosine ≥ `similarity_min` | Wrong-intent evidence or a reply that drifts off the question |
| `grounding` | Every sentence shares ≥ `grounding_jaccard_min` tokens/ngrams with some retrieved evidence response | A sentence supported by nothing retrieved |
| `unsupported_claims` | No completion-claim phrasing and no invented amount/date/order id/delivery time | "has been processed", "I have cancelled", "your refund is on its way", a made-up figure |
| `placeholder_safety` | No unresolved `{{…}}` token | Raw template text would reach the customer |
| `contradiction` | Neighbours agree on intent (≥ `neighbor_agreement_min`) and do not conflict procedurally | Retrieved examples point in different directions |

Verdicts:

| Verdict | Meaning |
|---|---|
| `accept` | All checks pass; serve the candidate as-is |
| `revise` | Fixable: action claims are softened into procedural wording ("You can request this by…"), placeholders become neutral phrases ("your order number"), ungrounded sentences are dropped; A5 serves the rewritten text |
| `flag` | Not fixable: contradiction, alignment failure after retry, or grounding that cannot be repaired |

Retry: when `intent_alignment` or `grounding` fails and a second supporting example exists, A4
sets `retry_candidate_rank = 2`; the pipeline asks A2 for the next-best candidate, audits that
once, and records both attempts in the trace. One retry maximum.

## 4. A5 — the single decision

| Input state | Decision | Response text |
|---|---|---|
| plan `clarify` | **CLARIFY** | Missing-item question from `slots.questions`, plus the fallback line ("If you cannot find your order number, reply with the email address…"); or "Are you asking about X or Y?" from `clarify_options` |
| plan `escalate` | **ESCALATE** | Handoff: what was detected, why, evidence, suggested queue, and an explicit statement that no changes were made |
| plan `answer` + audit `accept` | **ANSWER** | Candidate text, reasons `… + audit_accept` |
| plan `answer` + audit `revise` | **ANSWER** | Revised text, reasons `… + audit_revise` |
| audit `flag` on `contradiction` | **ESCALATE** | Handoff with `audit_flag`, `conflicting_evidence` and the conflicting examples |
| audit `flag` on `intent_alignment` | **CLARIFY** | The intent is uncertain: ask, do not guess |
| audit `flag` on grounding / claims / anything else | **ESCALATE** | Handoff with `unsupported_output` |
| `answer` route with no audit at all | **ESCALATE** | `unchecked_candidate` — an unaudited candidate is never served |

### Escalation queues (`nlp/a5.py::suggest_queue`)

| Trigger | Queue |
|---|---|
| `sensitive_legal_threat` | `legal-escalations` |
| `sensitive_fraud` | `fraud-review` |
| `sensitive_chargeback` | `payments-dispute` |
| `sensitive_harassment` | `trust-and-safety` |
| `sensitive_self_harm` | `crisis-support` |
| contradiction or audit flag | `quality-review` |
| gibberish / empty / out of distribution | `general-support` |
| otherwise | category queue (`refunds`, `order-support`, `account-support`, …) |

## 5. Hard guarantees

1. No output states that an order, payment, refund or account was changed, processed, cancelled,
   updated or shipped.
2. No amount, date, order number or delivery time appears unless it came from the query or from
   retrieved evidence.
3. No `{{placeholder}}` survives to the customer.
4. CLARIFY produces exactly one question about the missing item or the competing intents.
5. ESCALATE never offers to perform the action; it explains and routes.
6. Every decision carries at least one reason code and the agent trace that produced it.

These are asserted by [`tests/test_a4.py`](../tests/test_a4.py) (including a 500-response property
sweep) and [`tests/test_pipeline_l2.py`](../tests/test_pipeline_l2.py).

## 6. Changing the policy

```bash
# see what a retune would change, without writing
.venv/bin/python scripts/tune_a3_policy.py --dry-run

# rewrite config/l2_policy.json from DEV and keep the search log
.venv/bin/python scripts/tune_a3_policy.py

# re-run the evidence afterwards
.venv/bin/python scripts/eval_l2.py --sync
```

The tuner maximises accuracy on answered items subject to a minimum coverage, using DEV rows only.
TEST is read by the evaluation scripts, never by the tuner.
